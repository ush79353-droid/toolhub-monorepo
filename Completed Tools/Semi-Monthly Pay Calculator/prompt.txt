## 5. Core Wage Conversion Formulas

### Standard Assumptions

Unless an existing authorized project specification defines a different convention, use:

- 52 weeks per year.
- 12 months per year.
- 24 semi-monthly pay periods per year.
- 2 semi-monthly payments per month.
- Default 40 working hours per week.
- Default 5 working days per week.

**IMPORTANT:** Semi-monthly pay is not the same as biweekly pay.

Semi-monthly = 24 pay periods/year.

Biweekly = 26 pay periods/year.

Never use the biweekly divisor for semi-monthly calculations.

### A. When Hourly Wage Is Entered

`Weekly Wage = Hourly Wage × Hours per Week`

`Daily Wage = Weekly Wage / Days per Week`

`Yearly Wage = Weekly Wage × 52`

`Monthly Wage = Yearly Wage / 12`

`Semi-Monthly Wage = Yearly Wage / 24`

### B. When Daily Wage Is Entered

`Weekly Wage = Daily Wage × Days per Week`

`Hourly Wage = Weekly Wage / Hours per Week`

`Yearly Wage = Weekly Wage × 52`

`Monthly Wage = Yearly Wage / 12`

`Semi-Monthly Wage = Yearly Wage / 24`

### C. When Weekly Wage Is Entered

`Yearly Wage = Weekly Wage × 52`

`Daily Wage = Weekly Wage / Days per Week`

`Hourly Wage = Weekly Wage / Hours per Week`

`Monthly Wage = Yearly Wage / 12`

`Semi-Monthly Wage = Yearly Wage / 24`

### D. When Monthly Wage Is Entered

`Yearly Wage = Monthly Wage × 12`

`Weekly Wage = Yearly Wage / 52`

`Daily Wage = Weekly Wage / Days per Week`

`Hourly Wage = Weekly Wage / Hours per Week`

`Semi-Monthly Wage = Monthly Wage / 2`

### E. When Yearly Wage Is Entered

`Monthly Wage = Yearly Wage / 12`

`Weekly Wage = Yearly Wage / 52`

`Daily Wage = Weekly Wage / Days per Week`

`Hourly Wage = Weekly Wage / Hours per Week`

`Semi-Monthly Wage = Yearly Wage / 24`

All calculations must be mathematically consistent regardless of which wage field is the authoritative input.

## 6. Calculation Verification Example

Use this example for reasoning and manual correctness checks.

Inputs:

- Hourly wage: PKR 500
- Hours per week: 40
- Days per week: 5

Expected equivalent amounts:

| Wage Type | Expected Amount |
|---|---:|
| Hourly wage | PKR 500.00 |
| Daily wage | PKR 4,000.00 |
| Weekly wage | PKR 20,000.00 |
| Monthly wage | PKR 86,666.67 |
| Yearly wage | PKR 1,040,000.00 |
| Semi-monthly wage | PKR 43,333.33 |

Calculation:

`Weekly = 500 × 40 = 20,000`

`Yearly = 20,000 × 52 = 1,040,000`

`Semi-monthly = 1,040,000 / 24`

**Expected semi-monthly result: PKR 43,333.33**

Use unrounded values internally.

The reverse conversion from any equivalent wage should produce the same economic result within the display rounding tolerance.

## 7. Bidirectional Input Behavior — Critical

All five wage inputs must be editable.

However, only ONE wage field should be authoritative at a time.

Implement a robust last-edited-field model.

### Example

1. User enters Hourly wage = 500 PKR.
2. All other wage fields are calculated.
3. User changes Monthly wage to 100,000 PKR.
4. Monthly wage becomes the authoritative source.
5. The remaining hourly, daily, weekly, yearly, and semi-monthly amounts are recalculated.
6. User changes Hours per week from 40 to 35.
7. The calculator preserves the authoritative monthly salary and recalculates hourly equivalents accordingly.

### State Management Rules

- Track the last manually edited wage field.
- Maintain only one authoritative wage amount.
- Derive other wage fields instead of storing conflicting independent wage values.
- Do not cause circular React state updates.
- Avoid rounding accumulation during conversions.
- Do not overwrite a user-entered authoritative amount with a rounded derived value.
- Changing the hours/week or days/week must preserve the economic value of the authoritative wage.
- Changing a currency selector must perform the actual currency conversion without silently changing the economic value.
- Handle partially typed decimal values appropriately without prematurely overwriting the input.
- Clearing the authoritative input should clear dependent calculated wages and the result.
- Entering a valid zero wage should calculate zero, rather than be treated as an empty field.

Use existing project patterns for editing and formatting.
